# 🔍 2026-11-13 부검: AI 생태계 학습의 사각지대와 검증 과제

> **기록 목적:** 학습 과정에서 드러난 이해의 공백을 분석하고, 다음 학습에서 같은 문제가 반복되지 않도록 개선하기

## STAR 부검

### S — Situation (상황)

AI 서비스를 사용할 때 모델 이름이나 완성된 제품 중심으로 이해하기 쉬웠다. 모델 자체의 구조, 이를 실행하는 인프라와 제공자, API 및 하네스, 프롬프트와 컨텍스트 설계가 서로 연결되어 있다는 점은 전체적으로 정리되어 있지 않았다.

### T — Task (과제)

AI 생태계를 구성 요소별로 분해해 각 요소의 역할과 관계를 이해하고, 실제 작업에 적합한 모델과 제공 방식을 선택할 수 있는 기준을 만드는 것이 필요했다.

### A — Action (행동 및 원인 분석)

이번 학습에서 다음 항목을 정리했다.

1. **모델 계층:** LLM, Transformer, Embeddings, 프론티어 모델과 오픈웨이트 모델
2. **실행·제공 계층:** 하네스, 프로바이더, API 직접 호출, 로컬 및 클라우드 운영
3. **활용 계층:** Prompt, Instruction, Skill, Plugin, RAG, Ontology, Context
4. **평가 계층:** 테스트 결과, 사용자 선호, 공급자 사용량, 코딩·오픈소스 활용 데이터

다만 학습 방식에는 개선할 점이 있다.

- **개념 나열의 위험:** 용어를 폭넓게 정리했지만 각 요소가 실제 결과에 미치는 영향을 충분히 비교하지 못했다.
- **평가 기준의 혼동:** 벤치마크 점수, 사용자 선호, 사용량은 서로 다른 의미인데 하나의 순위처럼 받아들일 위험이 있다.
- **실습 근거 부족:** 동일한 과제를 여러 모델과 제공 방식으로 실행해 품질·속도·비용을 측정한 데이터가 아직 없다.
- **선택 기준의 추상성:** 비용·안정성·지속성을 중요 요소로 정리했지만 어떤 상황에서 무엇을 우선할지 구체적인 기준이 부족하다.

이는 특정 모델이나 서비스의 실패를 확인한 기록이 아니라, **개념 중심 학습이 실제 비교·검증으로 이어지지 않은 학습상의 공백**을 점검한 것이다.

### R — Result (결과 및 재발 방지)

이번 정리를 통해 AI 생태계를 모델 하나가 아닌 여러 계층의 연결 구조로 바라볼 수 있게 됐다. 동시에 개념을 이해한 것만으로 실무적인 선택 역량이 확보되는 것은 아니라는 한계를 확인했다.

같은 공백이 반복되지 않도록 다음과 같이 개선한다.

#### 재발 방지 액션

- [ ] 하나의 실제 과제를 정하고 비교할 모델/API 후보를 선정한다.
- [ ] 모든 후보에 동일한 입력과 프롬프트를 적용한다.
- [ ] 결과 품질, 응답 시간, 비용, 오류 및 안정성을 같은 기준으로 기록한다.
- [ ] Artificial Analysis의 벤치마크와 실제 과제 결과를 구분해 비교한다.
- [ ] Arena의 사용자 선호와 OpenRouter의 사용량을 각각 다른 지표로 해석한다.
- [ ] 선택 결과에 근거와 한계를 함께 기록하고, 다른 과제에서도 기준이 유효한지 재검증한다.

#### 검증 기준

| 항목 | 확인 질문 | 기록할 근거 |
|---|---|---|
| 품질 | 요구사항을 정확히 충족했는가? | 결과물과 평가 기준 |
| 속도 | 작업에 필요한 시간 안에 응답하는가? | 응답 시간 |
| 비용 | 반복 사용 가능한 비용인가? | 호출량·토큰·비용 |
| 안정성 | 여러 번 실행해도 결과가 일관적인가? | 반복 실행 결과 |
| 지속성 | 제공 방식 변경 시 대체 가능한가? | 대체 모델·API 경로 |

## 핵심 교훈

개념을 많이 아는 것과 실제 문제에 적합한 선택을 하는 것은 다르다. AI 생태계 학습은 용어 정리에서 끝나지 않고, 동일한 조건에서 비교하고 측정해 근거를 만드는 단계까지 이어져야 한다.

**재발 방지 원칙:** 다음부터는 새로운 기술을 학습할 때 '개념 정리 → 실제 과제 선정 → 동일 조건 실험 → 결과 측정 → 선택 근거 기록'의 순서를 지킨다.
