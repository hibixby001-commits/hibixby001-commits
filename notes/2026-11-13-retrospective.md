# 📝 2026-11-13 회고: AI 모델부터 활용 환경까지 이해하기

> **주제:** AI 모델·인프라·제공 방식·활용 도구를 하나의 생태계로 이해하기

## 오늘 학습한 내용

AI를 하나의 챗봇이나 모델로만 바라보지 않고, **모델 → 실행·제공 환경 → 목적에 맞는 활용 설계**라는 흐름으로 나누어 살펴봤다.

### 1. 모델과 기반 기술

- **LLM:** 대규모 언어 모델
- **Transformer:** 현대 언어 모델에서 널리 활용되는 핵심 아키텍처
- **Embeddings:** 텍스트 등의 정보를 벡터로 표현해 의미 기반 검색과 유사도 비교에 활용
- 모델을 직접 운영할 때는 학습 데이터, 파인튜닝, GPU 및 연산 인프라 등도 고려해야 한다.
- 프론티어 모델과 오픈웨이트 모델은 접근 방식, 운영 책임, 비용 구조가 다르다.

### 2. 하네스·프로바이더·API

AI 모델을 사용하는 방식에는 기업이 제공하는 완성형 서비스와 코딩 도구, API 직접 호출, 오픈웨이트 모델의 로컬·자체 인프라 운영 등이 있다.

서비스를 선택할 때는 편의성뿐 아니라 비용, 응답 속도, 안정성, 제공자 종속성, 대체 가능성을 함께 살펴야 한다.

### 3. 프롬프트와 컨텍스트 설계

- **Prompt / Instruction:** 작업과 규칙을 구체적으로 전달
- **Skill / Plugin:** 반복 작업과 외부 기능을 확장
- **RAG:** 외부 문서와 지식에서 관련 정보를 검색해 활용
- **Ontology:** 개념과 관계를 구조화
- **Context:** 작업에 필요한 정보와 맥락을 유지

좋은 결과를 얻으려면 필요한 맥락을 빠뜨리지 않으면서 불필요한 토큰 사용을 줄이고, 모델이 지시를 정확히 따르도록 작업 환경을 설계해야 한다.

### 4. 비교·평가 자료

| 평가 관점 | 참고 자료 | 확인할 내용 |
|---|---|---|
| 테스트 중심 | [Artificial Analysis](https://artificialanalysis.ai/) | 모델 성능·효율·속도·비용 |
| 사용자 중심 | [Arena Leaderboard](https://arena.ai/leaderboard) | 실제 사용자 선호와 비교 평가 |
| 공급자 중심 | [OpenRouter Rankings](https://openrouter.ai/rankings) | 모델 사용량과 공급 동향 |
| 코딩·오픈소스 중심 | [OpenCode Data](https://opencode.ai/ko/data/) | 코딩 도구와 오픈소스 생태계 |

## STAR 회고

### S — Situation (상황)

AI 서비스를 사용할 때는 눈에 보이는 챗봇이나 코딩 도구에 집중하는 경향이 있었다. 그 뒤에서 어떤 모델이 작동하고, 어떤 인프라와 제공자를 통해 서비스가 제공되며, 사용자가 이를 어떻게 조정할 수 있는지 전체 구조를 구분해서 이해하지 못했다.

### T — Task (과제)

AI 생태계를 모델, 실행·제공 환경, 활용 설계라는 층위로 나누어 이해하고, 특정 제품이나 모델 하나에 의존하지 않고 목적에 맞는 선택을 할 수 있는 기준을 정리하는 것이 과제였다.

### A — Action (행동)

1. LLM, Transformer, Embeddings 등 모델과 기반 기술의 개념을 구분했다.
2. 프론티어 모델과 오픈웨이트 모델, 완성형 서비스와 API 직접 호출, 로컬 운영의 차이를 정리했다.
3. 프롬프트, Instruction, Skill, Plugin, RAG, Ontology, Context가 활용 과정에서 맡는 역할을 살펴봤다.
4. Artificial Analysis, Arena, OpenRouter, OpenCode를 서로 다른 평가 관점의 자료로 분류했다.

### R — Result (결과 및 배운 점)

AI를 잘 활용한다는 것은 단순히 성능이 가장 높은 모델을 고르는 일이 아니라는 점을 배웠다. **어떤 모델을 선택할지, 어떤 방식으로 실행할지, 목적에 맞는 맥락과 도구를 어떻게 구성할지**를 함께 판단해야 한다.

또한 모델 평가는 하나의 순위로 결론 내리기 어렵다. 벤치마크, 사용자 선호, 실제 사용량, 코딩 환경에서의 활용성은 서로 다른 질문에 답하기 때문이다. 평가 기준은 사용 목적에 맞춰 선택해야 한다.

## 느낀 점과 다음 행동

이번 학습은 AI 생태계의 전체 지도를 그린 단계다. 개념을 아는 것과 실제 선택 기준을 갖는 것은 다르므로, 직접 실행하고 비교하는 경험이 필요하다.

- [ ] Artificial Analysis에서 관심 모델의 성능·속도·가격 비교
- [ ] Arena와 벤치마크 결과의 차이 확인
- [ ] OpenRouter에서 모델 사용량과 공급 동향 확인
- [ ] 동일한 작업을 여러 모델/API로 실행해 결과 비교
- [ ] 품질·비용·속도·안정성을 기록해 목적별 선택 기준 만들기

**한 줄 회고:** AI 활용 역량은 모델을 아는 데서 끝나지 않고, 모델을 제공·실행하는 환경과 작업 맥락을 함께 설계하는 능력까지 포함한다.
